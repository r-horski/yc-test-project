# Тестовое задание в Yandex Cloud

Этот проект предназначен для загрузки и обработки данных о заказах из JSON-файла в SQLite базу данных.

## Файлы проекта

- `orders.json` — исходные данные с информацией о заказах.
- `main.py` — основной скрипт для обработки данных.
- `db/orders.db` — SQLite база данных (создаётся автоматически).
- `logs/process.log` — логи выполнения (создаётся автоматически).
- `requirements.txt` — зависимости (пустой, так как используются только стандартные библиотеки).

## Как запускать скрипт

1. Убедитесь, что у вас установлен Python 3.6 или выше.
2. Склонируйте репозиторий (или скопируйте файлы в папку).
3. Запустите скрипт:
   ```bash
   python main.py
   ```

При первом запуске будут автоматически созданы директории `db` и `logs`, а также файл базы данных `orders.db`.

## Как устроен процесс

1. **Создание структуры БД**: скрипт создаёт таблицу `orders`, если она не существует.
2. **Чтение данных**: из `orders.json` загружаются все заказы.
3. **Обработка и вставка**: для каждого заказа извлекаются поля:
   - `order_id`
   - `status`
   - `date` (преобразуется из ISO-формата)
   - `amount`
   - `customer_region` (из вложенного поля `customer.region`)
4. **Проверка дубликатов**: перед вставкой проверяется, существует ли заказ с таким `order_id`. Если да — заказ пропускается.
5. **Логирование**: все ключевые шаги и ошибки записываются в консоль и в файл `logs/process.log`.

## Какие шаги логируются

- Запуск процесса
- Создание директорий
- Создание таблицы БД
- Количество загруженных заказов
- Пропущенные дубликаты
- Количество успешно добавленных заказов
- Ошибки при чтении JSON
- Завершение процесса

## Как реализована проверка дубликатов

Перед вставкой каждого заказа выполняется SQL-запрос:
```sql
SELECT 1 FROM orders WHERE order_id = ?
```
Если запись с таким `order_id` уже существует, заказ не вставляется повторно. Это гарантирует, что в базе не будет дубликатов по `order_id`. Поле `order_id` объявлено как `PRIMARY KEY`, что также обеспечивает уникальность на уровне СУБД.
